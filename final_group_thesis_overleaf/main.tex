\begin{abstract}
\noindent
This project investigates a federated intrusion detection framework for UAV swarms.
The system trains a CNN--LSTM IDS over windowed UAV network features with Flower
FedAvg while keeping raw packet data on simulated drone clients. A TrustNet-based
reinforcement learning bridge estimates per-UAV trust from client quality,
latency/resource proxies, loss, energy, and attack pressure. An adaptive privacy
controller then adjusts participation, update frequency, and Gaussian update
noise according to threat level, mission criticality, trust score, and resource
availability. The implementation includes ablation experiments for no-APC,
fixed-trust APC, and RL-trust APC variants, plus stress scenarios for malicious
updates, client dropout, low resources, and non-IID client data.
\end{abstract}

\section{Project aims and scope}
UAV swarms are useful in surveillance, emergency response, monitoring, and
precision agriculture, but their distributed nature exposes them to jamming,
spoofing, denial-of-service, reconnaissance, and compromised participant risks.
Centralised IDS training is poorly matched to UAV deployments because raw data is
sensitive, connectivity is intermittent, and onboard resources vary across
clients. The aim of this project is therefore to build and evaluate a federated
IDS workflow that detects UAV network attacks without centralising raw packet
features.

The implemented scope has four parts: (i) preprocessing Wireshark-style UAV IDS
features into sliding windows, (ii) federated CNN--LSTM training across drone
clients, (iii) RL-based trust modelling from per-round client context, and
(iv) adaptive privacy control over participation, update frequency, and update
noise. The project is a research prototype and dashboard demonstration rather
than a flight-certified UAV security product.

The literature review should connect three areas. First, UAV swarm security
surveys describe the attack surface of cooperative aerial networks, including
jamming, spoofing, routing disruption, and compromised nodes. Second,
federated-learning IDS work motivates local training under limited connectivity
and privacy constraints. Third, differential privacy and adaptive privacy
mechanisms in IoT explain the trade-off between utility, communication overhead,
and privacy protection. The implemented system combines these themes by using
federated training for IDS utility, RL trust estimation for participant
reliability, and APC rules for runtime privacy/resource adaptation.

\section{High-level system design (optional)}
The system contains five cooperating components. The preprocessing pipeline
converts UAV packet features into fixed-length windows and shards them across
clients. Each client trains a local CNN--LSTM IDS model and reports telemetry
summaries. The Flower server aggregates updates and evaluates the global model
on a pooled holdout set. The RL trust bridge maps each client to a state vector
\([quality, latency, loss, energy, attack]\), updates TrustNet from reward
transitions, and produces trust scores. The APC maps threat level, mission
criticality, trust score, and resource availability to the next round's
participation, update frequency, and privacy noise.

\section{Discussion}
The main interpretation should focus on the trade-off between IDS utility and
adaptive privacy/resource control. The APC may reduce participation or increase
update intervals under high threat or low resource conditions, which can protect
the global model and reduce communication but may slow learning. The current
Gaussian update-noise mechanism is an experimental privacy controller with
epsilon/delta logging; it should not be presented as a fully certified
differential-privacy accountant.

\section{Conclusions}
The implementation demonstrates an end-to-end UAV swarm IDS workflow where
federated learning, trust modelling, and adaptive privacy control interact
during training. The strongest evidence for the design should come from ablation
and stress-scenario experiments rather than from a single nominal training run.
