DATA · PIPELINE

数据集来源与 CNN+LSTM 建模

本页说明入侵检测张量如何从文献级 UAV 网络数据思想落地到仓库中的 dataset/ → data/swarm_processed/，以及 CnnLstmIDS（卷积 + LSTM）在全局 holdout 上的演示性准确率。

来源权威性：物理试验台与真实飞行采集

UAV-NIDD 对应论文发表于 IEEE Transactions on Network Science and Engineering（2025，DOI 10.1109/TNSE.2025.3553442）；原始流量见 Figshare。公开仓库与说明由 KAUST CyberSar Lab 维护，与论文同源，便于复核与引用。

与「仅仿真标签」不同，该数据集强调在真实 UAV 网络试验台上采集，并在真实飞行过程中同时记录正常与攻击条件下的网络流量。以下两段为官方 README 中的英文原文摘录（与论文表述一致），用于说明数据来自实机而非虚构场景：

“UAV-NIDD is a real-world, dynamic intrusion detection dataset collected from a physical UAV network testbed. It includes benign traffic and ten cyber-attack types targeting UAVs, access points, and ground control stations, designed to support research in UAV cybersecurity, IDS, and machine learning.”

“Traffic was captured during real flight operations under both benign and attack conditions.”

摘录出处：CyberSaR-KAUST/UAV-Intrusion-Detection-Dataset 仓库 README（论文配套发布）。

文献与数据对齐

学术基准：UAV-NIDD: A Dynamic Dataset for Cybersecurity and Intrusion Detection in UAV Networks。该工作在物理 UAV 网络试验台上采集正常与多类攻击流量，并提供面向 UAV 入侵检测研究的公开资源（原始 PCAP 等见 Figshare DOI 10.6084/m9.figshare.25486462）。

本仓库在 dataset/ 中维护按攻击类别分文件的表格化流量特征（Wireshark 风格字段列，与 Case1 特征命名对齐），覆盖暴力破解、DDoS、去认证、伪造降落、干扰、MITM、侦察、扫描、UDP/ICMP 洪水及正常类等，与 UAV-NIDD 一文强调的 UAV 网络多类入侵检测场景一致；随后经统一脚本做时间排序、缺失列补零、标准化与滑窗，供联邦与集中式评估共用。

清洗与滑窗（preprocess_swarm_federated.py）

  1. 从各 CSV 读取与 data/UAV-Case1-Label.csv 表头一致的 44 维无线/网络侧数值特征（缺列补零，非数值列因子化）。
  2. 按 frame.time_epoch / frame.number 做时间顺序排列。
  3. 在「各文件前 75% 包」拼成的训练包络上拟合 StandardScaler，并写入 packet_scaler.pkl；对全量包做变换。
  4. 以 窗口长度 16、步长 16 将包序列切成样本；窗口标签取窗内包的多数类。
  5. 每个源文件的末 25% 包仅进入全局测试池，汇总为 test.npz；训练窗按类别分层轮询拆成 9 份 train_split_*.npz，供三机联邦分片。

合成机载遥测（enrich_swarm_telemetry.py + telemetry_synth.py）

在 44 维 IDS 特征上为每个时间步拼接2 维与流量对齐的合成遥测：电池 SOC（%）与 CPU 利用率（%），使每个窗口形状为 16×46，与当前 meta.json 中 n_features=46 一致，再输入 CNN+LSTM。

模型与评估

分类器为仓库内 model.py 的 CnnLstmIDS：对每架机的窗口张量先做 1D 卷积提取局部模式，再用 LSTM 建模跨包时序，最后 softmax 输出 num_classes 类入侵/正常标签。全局泛化指标在服务器持有的 test.npz 上做一次集中式前向（与联邦轮次日志中的 centralized eval 一致）。

误报与飞行安全：为何在 UAV 上更关键

机载 IDS 若误报率（把正常流量判成攻击 / False Positive）偏高，在真实飞行中往往比「漏报一次」更难承受：频繁告警会驱动链路保护、会话隔离或自动化处置反复触发，造成数传 / 指控链路抖动甚至中断；在带宽与能量本就受限的空域任务里，这种不稳定会显著抬升失控、迫降乃至坠机的风险。因此，对无人机而言，在可接受检出能力前提下保持相对较低的误报，常常是系统能否长期在线的首要约束。

本仓库在 CnnLstmIDS 的训练与集中式评估中，除整体准确率外，同时关注Macro 精确率 / 召回等类均衡指标（见下方演示卡片），用于抑制「少数类被滥报、多数类正常流量被大面积误判」的倾向。若需对外给出窗口级误警率（FAR）或正常类上的假阳性比例，应在 holdout 集上基于混淆矩阵单独统计并与任务放行策略一并标定。

SIM · WORKFLOW

无人机边缘安全闭环

点击下方一个按钮即可触发完整链路：向服务器取得本机训练参数 → 在板端对 test.npz 中的真实窗口张量运行本地 CnnLstmIDS（若存在 checkpoints/fl_global_last.pt 则加载联邦权重；否则使用随机初始化的演示权重，结论仅作流程示意）→ 按 softmax argmax 判定是否告警及类别 → 模拟上行上报 → 服务器侧调用 AdaptivePrivacyController 输出下一轮 participate / noise_scale / freq_n（freq_n 为「每 N 轮上传一次」；低威胁时常为 1，威胁升高或资源紧张时在 APC 配置区间内增大）。

分步运行后端流程

必须在 dashboard 目录启动 python serve.py，页面与 /api/fl-control / /api/uav-workflow 同源；分步按钮会拉起服务器与三机终端，训练阶段调用 uav_workflow_sim.py 读取 data/swarm_processed/test.npz。

freq_n：每 N 个联邦全局轮才允许上传一次本地更新（与 apc_module/rules.py 中 frequency 规则一致：常态多为 1，高威胁时 N 增大）。participate=0：本轮不参与聚合，仅回传全局权重。
