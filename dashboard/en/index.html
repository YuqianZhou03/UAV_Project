Dataset provenance & CNN+LSTM pipeline

How tabular UAV-network traces become data/swarm_processed/ windows, how they are cleaned, how synthetic telemetry is fused, and what CnnLstmIDS (CNN + LSTM) achieves on the global holdout in this dashboard snapshot.

Authority: physical testbed & real-flight captures

The UAV-NIDD paper is published in IEEE Transactions on Network Science and Engineering (2025, DOI 10.1109/TNSE.2025.3553442); raw captures are on Figshare. The official README and repository are maintained by KAUST CyberSar Lab and match the paper’s description—easy to audit and cite.

Unlike purely synthetic labels, UAV-NIDD stresses a physical UAV network testbed and traffic recorded during real flight under benign and attack conditions. The two English excerpts below are taken verbatim from that README (same wording as the paper’s companion release) to show the data are field-captured, not fictional scenarios:

“UAV-NIDD is a real-world, dynamic intrusion detection dataset collected from a physical UAV network testbed. It includes benign traffic and ten cyber-attack types targeting UAVs, access points, and ground control stations, designed to support research in UAV cybersecurity, IDS, and machine learning.”

“Traffic was captured during real flight operations under both benign and attack conditions.”

Source: CyberSaR-KAUST/UAV-Intrusion-Detection-Dataset README (paper companion).

Paper alignment

Academic reference: UAV-NIDD: A Dynamic Dataset for Cybersecurity and Intrusion Detection in UAV Networks — benign and attack traffic from a physical UAV-network testbed, released for IDS research (raw captures via Figshare DOI 10.6084/m9.figshare.25486462).

This repository keeps per-attack CSV feature tables under dataset/ (Wireshark-style columns aligned with the Case1 header), spanning brute-force, DDoS, de-auth, fake landing, jamming, MITM, reconnaissance, scanning, UDP/ICMP flooding, and normal traffic — consistent with the multi-class UAV intrusion setting discussed in UAV-NIDD. A single preprocessing pipeline then sorts in time, fills missing fields, standardizes, and windows packets for both federated training and centralized evaluation.

Cleaning & windows (preprocess_swarm_federated.py)

  1. Load 44 numeric / factorized features per row, matching data/UAV-Case1-Label.csv (missing columns become zeros).
  2. Sort packets by frame.time_epoch / frame.number.
  3. Fit StandardScaler on the training envelope (first ~75% of each file, concatenated), save packet_scaler.pkl, transform all packets.
  4. Slice length-16, stride-16 windows; assign each window the majority label of packets inside.
  5. Send the last 25% of each source file only to the pooled test split (test.npz); stratify training windows into nine train_split_*.npz shards for three UAV clients.

Synthetic onboard telemetry (enrich_swarm_telemetry.py + telemetry_synth.py)

Append two channels per timestep — battery SOC (%) and CPU utilization (%) — aligned with traffic intensity, yielding tensors of shape 16×46 as in meta.json (n_features=46) before CNN+LSTM.

Model & evaluation

model.py defines CnnLstmIDS: 1D convolutions over per-packet features, an LSTM over the 16-step sequence, then softmax over num_classes labels. Centralized accuracy / loss / macro P/R are computed once per logged round on the global test.npz holdout held by the server.

False alarms & flight safety: why they matter more on UAVs

A high false-positive rate (benign traffic classified as an attack) is often harder to tolerate in real flight than an occasional miss: repeated alarms drive link-hardening, session isolation, or automated responses, which can make the telemetry / command link jitter or drop. On bandwidth- and power-limited aerial links, that instability sharply raises the risk of loss of control, forced landing, or crash. For UAV operations, keeping false alarms comparatively low—while preserving useful detection—is frequently the binding requirement for keeping the system online.

Training and centralized evaluation here track macro precision / recall alongside overall accuracy (see the cards below) to reduce “a few classes dominate false alarms” behavior on multi-class UAV traffic. If you need a published false-alarm rate (FAR) on benign windows, compute it explicitly from a confusion matrix on the holdout set and align it with your mission’s gating policy.

SIM · WORKFLOW

UAV edge security closed loop

The workflow now runs in three stages: start the server terminal, start three UAV terminals, then trigger training/simulation. During stage 3, CnnLstmIDS runs on window tensors from test.npz (loading checkpoints/fl_global_last.pt when present) and then uplinks verdicts to AdaptivePrivacyController for next-round participate / noise_scale / freq_n.

Run backend simulation

Start python dashboard/serve.py from the repository root so this page and /api/fl-control share the same origin. The handler imports uav_workflow_sim.py from the repository root and reads data/swarm_processed/test.npz.

freq_n: uplink once every N federated rounds. participate=0: skip aggregation for this round and only receive global weights.
